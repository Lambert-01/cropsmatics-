# Scientific Data Validation

Reviewed: 2026-10-28 on feature branch `codex/final-excellence-2026`.

## Executable release gate

Run after rebuilding the data pipeline:

```bash
make data
make scientific-validation
```

The command writes `data/interim/scientific_validation_report.json` and
`data/interim/scientific_validation_report.md`. It never edits a published
value. `PASS` means the software/data contract held. `FAIL` means a release
defect. `UNRESOLVED` means an official source or environment limitation is
visible and still needs review. `SKIP` means evidence was unavailable.

## Current local evidence

The validation command was run against the current processed panel and produced:

| Check result | Count |
|---|---:|
| PASS | 11 |
| FAIL | 0 |
| SKIP | 0 |
| UNRESOLVED | 2 |

The panel contains 6,156 rows, 14 published periods (`2022A` through `2026B`),
30 district codes and 17 canonical crops. It has no synthetic rows. The natural
key includes geography, crop and `farmer_scale`; national total, SSF and LSF
rows are therefore not falsely treated as duplicates.

## What is checked

- Published period dimension and current district/crop dimensions.
- Non-negative area, production and yield values.
- Natural-key uniqueness.
- Source ID, workbook, sheet, metric-table map, source row and processing
  version lineage.
- Source IDs against `data/source_registry/sas_sheet_inventory.csv`.
- 2025B precedence: `NISR_SAS_2025_ANNUAL` and
  `SAS 2025_Annual Tables.xlsx` are the serving source.
- Yield reconciliation using `1000 * production_mt / harvested_area_ha`.
- Manifest pipeline version and code/data-build commit alignment.

## Unresolved findings

The current processed evidence has 89 material published-yield
reconciliation findings and 4,929 rows within the documented tolerance. This
is a source-quality finding, not permission to overwrite NISR's published
yield. The affected rows remain flagged for review and are excluded from
forecast training where the existing ML gate requires it. The complete row
list remains in the pipeline validation report and source audit.

The processed manifest was generated by an earlier commit than the code under
review. That is intentionally visible. Before a release, run `make data` and
`make scientific-validation` so the manifest, report and submitted code share
one commit identity.

## Traceability boundary

Each canonical row includes workbook, sheet list, metric-to-table mapping and a
source-row reference. `source_row_min` is not an exact Excel cell address when
one observation combines several source tables. The UI and API must describe it
as a row-level reference; a metric-keyed cell sidecar remains future work.
