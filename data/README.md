# Cropmatics Rwanda Data Layer

This directory contains the authoritative data inputs, dictionaries and generated analytical outputs used by Cropmatics Rwanda.

## Directory layout

```text
data/
├── raw/                         # IMMUTABLE official/source inputs and extracts
│   ├── nisr/
│   │   └── sas/                 # 2022–2026 NISR releases: workbooks/ and tables/
│   ├── external/
│   │   └── minagri/             # Verified MINAGRI post-harvest/storage context
│   ├── markets/                 # Provider drop-folder; currently no verified observations
│   └── cropmatics_real_data_2024_2026/  # verified 2025B compatibility pack
├── dictionaries/                # Crop/geography/code mappings and variable contracts
├── source_registry/             # Dataset provenance and access terms
├── interim/                     # Regenerable pipeline intermediates (gitignored)
├── processed/                   # Regenerable canonical analytical tables (gitignored)
└── external/                    # Future third-party derived/open inputs (gitignored)
```

## What is authoritative

1. **Official raw inputs live under `data/raw/` and are immutable.** Never edit these files in place. Corrections, normalisation and mappings belong in `scripts/data/` and write to `interim/` or `processed/`.
2. **`data/raw/nisr/sas/` is the multi-season statistical source layer.** It contains published 2022A–2026B extracts plus year/release `workbooks/` folders. The reviewed mapping in `scripts/data/sas_table_map.py` determines which sheets are ingested. Owner-supplied XLSX files are untracked; the tracked CSV extractions and manifest are the Docker inputs.
3. **`data/raw/cropmatics_real_data_2024_2026/` remains as a verified compatibility pack and provenance bridge.** Its CSVs are derived from the official NISR/MINAGRI source archive and are active source inputs. The compiled convenience workbook was removed because it duplicated those CSVs. The distinct curated 2025B original remains unchanged at `data/raw/nisr/sas/2025/season_b/workbooks/Tables_2025_Season_B_0_curated_official.xlsx`.
4. **MINAGRI storage/post-harvest inputs under `data/raw/external/minagri/` are retained** because the active pipeline builds the storage infrastructure and cold-chain context from them.
5. **No fabricated dataset is stored under `data/`.** Automated tests use temporary fixtures created inside test runs; those values never enter the production analytical tables.

## Original source view

The web Data Explorer has two separate tabs:

- **Processed datasets** shows the normalized, API-ready analytical tables used
  by dashboards and models.
- **Original SAS sources** shows the worksheet cell grid retained in
  `data/raw/nisr/sas/`. It keeps source row order, headers, blank cells and
  spacer rows, and provides the exact worksheet extract or original workbook
  download when that file is present in the deployment.

The API builds this source catalogue from `manifest.csv` and
`source_registry/sas_sheet_inventory.csv`. An inventory record without a
deployed cell file is still listed for auditability and is labelled
**Inventory only**; it is never replaced with a processed table or fabricated
cells. The tracked curated 2025B workbook is available where packaged, while
owner-supplied workbooks that remain gitignored can appear as inventory-only in
the deployed image.

## Generated data

`data/interim/` and `data/processed/` are generated by the pipeline and intentionally ignored by Git except for `.gitkeep` placeholders.

Rebuild all generated analytical data with:

```bash
make data
```

The deterministic pipeline ingests mapped SAS tables, builds the multi-period
productivity/practice/post-harvest outputs and 2025B compatibility tables,
validates them, and records a content-addressed manifest. Its exact current
order is defined in `scripts/data/run_all.py`.

## Multi-season SAS rules

- Period comes from the reviewed table mapping, not blindly from a worksheet title.
- Only published periods are allowed; no unpublished season is invented.
- Blank cells remain null. Missing observations are never coerced to zero.
- Aggregate and district rows remain explicitly separated by geography/scope fields.
- Raw yield is never averaged across unrelated crop species for comparison.

The principal multi-season output is `processed/crop_productivity.csv`, containing the canonical period × geography × crop panel.

`processed/district_crop_productivity.csv` is retained as a generated compatibility table for the current release cycle and is validated against the corresponding rows of the canonical panel.

## Market prices

`scripts/data/ingest_market_prices.py` reads provider exports from `raw/markets/<provider>/` and writes `processed/market_price_observation.csv`.

At present no verified provider export is committed, so the pipeline writes the canonical schema with **zero observations**. Cropmatics must not fabricate market prices to fill that gap.

## Cleanup policy

Superseded derived CSV copies that previously lived under `data/interim/legacy_official_derived/` were removed because they duplicated authoritative raw inputs and were excluded from `scripts/data/run_all.py`.

Future deletion is allowed only when all of the following are true:

1. the file is not an immutable raw source needed for provenance;
2. no pipeline step, API, model, test or documentation contract consumes it;
3. an authoritative replacement exists where applicable; and
4. the complete pipeline and tests still pass after removal.

Git history remains the archive for removed superseded derived artefacts.

## Source-only cleanup completed

The repository no longer includes the fabricated demo harvest CSV, its synthetic
README, or duplicate compiled convenience workbooks. The complete NISR worksheet
archive, source manifests, real compatibility CSVs, MINAGRI context CSVs,
dictionaries, and reproducible generated outputs remain available. Unmapped SAS
worksheets are retained as source evidence even when they do not feed a current
feature.
